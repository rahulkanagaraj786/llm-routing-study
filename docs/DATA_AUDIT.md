# Data audit

Date: 2026-11-15. Numbers are regenerated by `scripts/00_audit.py` into
`results/audit/data_audit.json`. These are facts about the recorded data (accuracy, cost,
missingness of the two LLMs), not router results.

## What was checked and how

| Check | Result |

| Handoff ZIP data hash | matches `checksums.json` |
| Raw archive | downloaded from Hugging Face at the pinned revision; sha256 and byte count match the handoff provenance |
| Paired table rebuilt from raw | scores and costs equal the package for all 10,918 rows; eligibility equal (10,367) |
| Model identifiers | every file used has `model_name` `gpt-5` or `gemini-2.5-flash`; `gpt-5-chat` is a separate directory and is not used |

| Same ground truth | equal for all rows |
| Binary scores | only 0.0 and 1.0 in all nine benchmarks used |
| Exact duplicates | one: the same question appears in MMLU-Pro and HLE (the HLE copy is ineligible) |
| Near duplicates | 160 groups (381 rows) at cosine ≥ 0.85, mostly SimpleQA questions that differ by a year or ordinal; grouped so they cannot straddle splits |
| Pilot reproduction | does not reproduce exactly on this machine (see issue 1) |

## Material issues

### 1. The pilot does not reproduce exactly across machines
Same data, same pinned package versions, same seeds, same splits and baselines, but
different savings (1 pp allowance: logistic 4.26% here vs 4.72% historical; forest 3.57%
vs 3.44%; individual runs differ by up to 1.3 points).

Most likely cause: `TfidfVectorizer(max_features=12000)` keeps the 12,000 most frequent
terms, and 388–497 of those slots are filled from about 1,170 terms tied at the cut-off
frequency. scikit-learn breaks the tie with an unstable sort whose result depends on the
CPU's sort implementation. This could not be confirmed on the original machine. The new
pipeline breaks ties by the term itself, so its vocabulary is deterministic.

Consequence for the study: a change of a few hundred rare features moved savings by about
a point, so differences of that size between candidates are noise.

### 2. Provenance covered five of seven benchmarks
`source_provenance.json` lists LiveCodeBench, GPQA, LiveMathBench, AIME and MMLU-Pro. The
paired file also contains SimpleQA and HLE (57% of eligible questions). Both are in the
same pinned archive and match it exactly; `data/processed/paired_v2_provenance.json` now
records all files with hashes. The provenance also lists `mmlupro/test_1000`, which the
paired file does not use (it is a subset of `test_3000`).

### 3. Score semantics differ by benchmark
All scores are 0/1, but they come from different graders:
- SimpleQA: an LLM judge assigns A (correct), B (incorrect) or C (not attempted); only A
  scores 1. GPT-5 has 267 "not attempted" answers scored 0.
- HLE: free-form answers judged for correctness.
- MMLU-Pro, GPQA: multiple-choice letter match.
- LiveCodeBench: test-case execution. AIME, LiveMathBench: final-answer match.
Y therefore mixes judge-based and exact-match correctness. This is a property of the
benchmark, stated as a limitation.

### 4. HLE: 507 GPT-5 records have cost 0.0, and 499 are recoverable
The first ~500 HLE test records carry tokens, a response and a score but a cost of 0.0.
The identical responses (same text, same token counts) appear in `hle/subset_500` with a
recorded cost. Accuracy of the affected records is the same as the rest (26.0% vs 26.4%),
so excluding them loses sample size, not representativeness. Default: excluded, as in the
pilot (1,631 eligible HLE). Using the sister-file cost would give 2,130. Team decision.

### 5. LiveCodeBench Flash costs are below the price schedule
Everywhere else, recorded cost equals tokens × ($1.25, $10.00) per million for GPT-5 and
($0.30, $2.50) for Flash, to rounding. For Flash on LiveCodeBench half the records are
at 20–30% of that, and the total is $6.16 recorded vs $8.46 at the schedule. Recorded
costs stay primary; the final evaluation also reports savings at list prices.

### 6. Zero-cost and empty-response records
Besides those 507 HLE rows, 44 corpus rows are excluded for a zero cost or an empty
GPT-5 response (SimpleQA 11, MMLU-Pro 7, HLE 20, AIME 2, LiveMathBench 4). Empty GPT-5 responses are
scored 0 in the release, so excluding them slightly favours GPT-5's baseline accuracy.

### 7. Flash is not always the cheaper model
Flash cost more than GPT-5 on 261 eligible questions (191 in HLE). The cost ratio ranges
from 91× on SimpleQA to 1.9× on AIME. Sending a question to Flash is not always a saving,
and the cutoff search accounts for that because it uses recorded per-question costs.

### 8. Domain labels are thin and benchmarks are mixed
- Only three coarse domains: knowledge (9,137), code (1,055), math (175).
- The math holdout is small: 175 questions, 28 of them with Y = +1.
- MMLU-Pro prompts name their subject ("Answer the following math question…"), so its
  359 math and 100 computer-science questions can be removed for the transfer study.
- HLE has no subject field in this release and mixes subjects, so it is removed entirely
  from training in the code and math holdouts.

### 9. GPT-5 reasoning effort is not recorded
The files say `gpt-5` only. The SWE-bench file name contains `gpt-5-medium`, and GPT-5's
completion-token counts (about 1,200 tokens for a one-line SimpleQA answer) show a
reasoning configuration, but "medium" is not verifiable from the data for the corpus
benchmarks.

### 10. Benchmark identity is visible in the prompt
Each benchmark has its own instruction template, and SimpleQA questions are a single
short sentence. A router can learn "this looks like MMLU-Pro" without benchmark identity
being a feature. Per-benchmark results are needed to see whether savings come from
question-level signal or from routing whole benchmarks.

### 11. Other GPT-5 / Flash pairs in the release, not used
- ArenaHard and its three subsets: scores are 0, 0.5 or 1, not binary correctness.
- tau2: the `prompt` field is a test description, not what the model saw.
- ARC-AGI v1 and SWE-bench Verified: binary, paired, never in the pilot corpus, but from
  the same archive, so not newly collected data. By team decision (2026-11-16) ARC-AGI
  is an optional check after the router is frozen and SWE-bench is not evaluated. Of
  SWE-bench's 500 matched instances, 491 are eligible (9 have an empty GPT-5 response).
  SWE-bench is notable: Flash scores higher than GPT-5 there (18.1% vs 16.1%).
